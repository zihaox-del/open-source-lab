# Open Source Lab

一个面向真实需求的小型开源工具孵化仓库。目标不是堆想法，而是把值得解决的问题推进成可运行、可测试、可发布、可维护的工具。

## 长期主线

```text
真实痛点 -> 可运行工具 -> 测试与说明 -> 发布版本 -> 用户反馈 -> 持续维护
```

这六步也是项目的完成定义。没有用户问题不立项，没有可运行结果不演示，没有测试和说明不发布，没有反馈不扩功能。

## 项目进入条件

一个候选项目必须回答：

1. 谁遇到了什么具体问题？
2. 现有方案为什么不够用？
3. 最小版本能在一周内交付什么？
4. 用什么证据证明它有用？
5. 是否可以在不泄露公司或客户材料的前提下公开？

## 生命周期

- `提案`：写清问题、用户和验收指标。
- `孵化`：完成可运行版本、测试和使用说明。
- `候选发布`：补齐许可证、安全说明、版本记录和维护边界。
- `独立仓库`：达到发布门槛后拆出单独仓库持续维护。
- `归档`：需求不成立或维护成本过高时，保留结论并停止投入。

## 目录

- `projects/`：正在验证的工具。
- `docs/maintainer-playbook.md`：维护者工作方式和发布门槛。
- `.github/ISSUE_TEMPLATE/`：项目提案模板。
